# TCT Reader Kit

Two blocks for Tee Corley Travels post sidebars:

- **Table of Contents** — auto-generated links to the post's own H2/H3 headings
- **Newsletter Signup** — collects subscriber emails into WordPress

No build step. The PHP renders everything; the editor file is plain JS, so you can
edit any file in place without npm.

## Install

Plugins → Add New → Upload Plugin → choose `tct-reader-kit.zip` → Activate.

## Using the blocks

Both appear in the inserter under the **Theme** category. Add them to the sidebar
column of the Single Posts template (Appearance → Editor → Templates → Single Posts).

Shortcode equivalents, if you'd rather drop them into a single post:

```
[tct_toc heading="Contents" maxlevel="3" sticky="1"]
[tct_newsletter heading="Join My Newsletter" button="Subscribe" showname="1"]
```

## Where the emails go

**Subscribers** in the admin menu. Each row stores the email, optional first name,
status, which post they signed up from, and a consent timestamp. **Export CSV** is at
the top of that list.

The list is restricted to administrators — every capability is mapped to
`manage_options`, so Editors and Authors can't read it. IP addresses are stored
**hashed**, never in the clear.

### This plugin collects; it does not send

There is deliberately no sending feature. When you're ready to actually email people,
hook the action rather than modifying this plugin:

```php
add_action( 'tct_rk_subscriber_added', function ( $email, $name, $post_id ) {
    // Forward to Mailchimp / Kit / Buttondown here.
}, 10, 3 );
```

Before you send your first campaign, you'll need an unsubscribe link and a physical
mailing address in the footer to comply with CAN-SPAM. Every subscriber row already
has a `_tct_token` value stored for building unsubscribe URLs. An email service
provider handles all of that for you, which is why this plugin stops at collection.

## Design notes

Two decisions that look like omissions but aren't:

**No nonce on the signup form.** It's a public unauthenticated form whose only effect
is adding an address to a list. A nonce blocks nothing a spammer couldn't do by
POSTing the endpoint directly, but it *would* break real signups — nonces expire, so
anyone who opens a post and subscribes a day later fails, and a full-page cache serves
one baked-in nonce to every visitor until it goes stale. Spam is handled by a
honeypot, a 2-second time trap, and a per-IP rate limit (5/hour). A same-origin
referer check is applied where a referer is present.

**The time trap has no upper bound.** Only submissions faster than 2 seconds are
rejected. An upper bound would silently discard genuine signups from cached pages,
where the embedded timestamp is always old.

## Changelog

### 1.0.1

Two bugs found by testing on the live site.

**Fixed: the plugin broke `manage_options` site-wide.** 1.0.0 mapped the post type's
`edit_post` / `read_post` / `delete_post` capabilities to `manage_options`. Those three
are *meta* capabilities, and WordPress passes them through
`_post_type_meta_capabilities()`, which registers whatever they point at into the
global `$post_type_meta_caps` map. That registered `manage_options` itself as a meta
capability, so every `current_user_can('manage_options')` call anywhere on the site was
re-mapped to `edit_post` with no post ID and resolved to `do_not_allow`. Symptoms: the
Settings menu disappeared and the Subscribers screen returned 403 to administrators.
Only primitive capabilities are remapped now, and the post type uses its own
`capability_type` so generated meta-cap names are namespaced. Covered by a regression
test that runs the plugin's real arguments through WordPress's own
`get_post_type_capabilities()`.

**Fixed: a sticky table of contents overlapped anything below it.** A sticky element is
shifted visually without moving its siblings, so the TOC slid over the newsletter box
while scrolling. Sticky now applies only via `:last-child`, so the option becomes inert
whenever something follows the TOC in the same column.

## Known limitation

The table of contents reads the post's stored content, so headings that only exist
after rendering — inside a synced pattern or reusable block — won't appear in the
list. Headings written directly in the post always do. Anchor ids and TOC links are
generated by the same deterministic slug function, so they can't drift out of sync.
